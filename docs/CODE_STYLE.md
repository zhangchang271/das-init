# MATLAB 代码与命名约定

本约定记录当前能从项目代码中直接观察到的写法，并区分科学流程来源和部署封装。它是后续维护 `das-init` 的参考，不声称覆盖用户所有项目的个人偏好。

## 学习样本和适用范围

1. **首要样本：** `/csim2/zhangchang/matlab/SJDASTest/run_sjdas_dasqt_mccfjflow2manual.m`（SHA-256 `9d56e233e556584524accafb0d84da95d33c7d9e47fdd6b9e182df22e0f15013`）。这是 San Jose 测试中用于得到当前正确结果的 MATLAB 主控；仓库 `vendor/manifest.json` 记录了该指纹。参数、数据流、变量命名和结果处理以这个版本为准。
2. **流程来源：** `/csim2/zhangchang/matlab/NyHtQInv/mainline6p0/MCCFJFLOW2Manual.m`。它能说明 MCCFJFLOW2Manual 的组织方式及沿用的局部函数，但其 48 h、采样率、孔径、滤波和 mute 参数属于另一个项目，不能照搬为 San Jose 默认值。
3. **部署样本：** `matlab/run_pipeline.m` 与 `matlab/workflow_config.m`。这两份代码为独立部署增加了 `cfg` 配置、阶段入口和路径适配。它们适合参考部署边界，不应单独用来推断科学主流程原本的变量风格。
4. `vendor/matlab/` 中的 `mCCFJ`、`EDWav` 和 mute 函数定义算法接口；它们的命名属于既有 API，应保持原样，但不等同于主控脚本的个人风格。

## 当前能确认的写法

- MATLAB 承担科学计算主流程；主脚本按 `%%` 和编号分阶段，参数按预处理、筛选、CCF、F-J 等步骤分组。中文注释解释目的、参数意义、缓存影响和人工操作。
- 采用直接、顺序的数据流和局部辅助函数。部署版可在入口读取 `cfg`，进入计算后仍把配置字段映射为有意义的局部变量；算法函数的输入输出保持显式。
- 一般变量使用描述性的 `lower_snake_case`，例如 `segment_seconds`、`ccf_frequency_normalization`、`pick_seed_frequency`。已有科学/API 记号如 `Fs`、`CC`、`FJ`、`EDWav`、`mCCFJ` 保留原大小写；迁移时不要为风格统一改名。
- 新增变量名尽可能标明物理量和单位，例如 `_s`、`_hz`、`_m`、`_mps`。既有公共配置字段若已有使用者，不为补单位后缀而静默改名；必要时在接口说明中明确单位。
- MATLAB 波形约定为时间 × 道；频谱和 F-J 的维度遵从各自接口。函数入口、返回值及保存变量应就近注明维度、轴和单位。转置应显式可见，不依赖含糊的行列假设。
- 调用会返回更新结构体的算法函数时，显式接收返回值，例如 `CC = mCCFJ.stack_bin(CC,width)`。跨步骤传递物理量时保留原处理历史和必要计数，不用绘图归一化替代科学数据。
- 主控脚本变量名和已验证中间 MAT 字段属于可追溯接口；重构时先确认仓库约定和下游读者，再决定是否更名。

## 后续改动规则

- 优先沿用首要样本已有的变量名、阶段顺序、参数分组和算法调用方式；新增代码按上述可观察约定命名。
- 区分“用户原流程”与“为了部署新增的封装”。如需改成函数、配置结构或命令行接口，应限于部署边界，并在接口文档解释映射关系。
- 变量命名不能代替数据契约。改动输入或输出时，同时更新 `CONTRACT.md` 中的函数参数、数组维度、轴、单位、物理含义和验收方式。
- 正负时间支、归一化、FFT 长度、日期或窗口参数属于科学处理定义；不要为了代码整洁而合并、重命名或改公式。
- 需要确认更广泛的个人偏好时，继续查看用户明确指定的同类原始 MATLAB 程序；不要把单个部署文件或第三方库风格当作证据。
